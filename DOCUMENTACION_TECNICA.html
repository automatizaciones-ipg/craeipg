Módulo de Autenticación

Implementado con auth-astro v4 + @auth/core v0.34, proveedor Google OAuth 2.0.

Configuración (auth.config.ts)

import Google from "@auth/core/providers/google";
import { defineConfig } from "auth-astro";

export default defineConfig({
  providers: [ Google({ clientId: process.env.GOOGLE_CLIENT_ID, clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      authorization: { params: { prompt: "select_account" } } }) ],
  trustHost: true,
  secret: process.env.AUTH_SECRET,
  session: { maxAge: 8 * 60 * 60 },   // 8 horas FIJAS — sin rolling
  callbacks: {
    async signIn({ profile }) {
      // Restricción de dominio — capa 1
      const email = profile.email.toLowerCase();
      return ["@ipg.cl", "@alumnos.ipg.cl"].some(d => email.endsWith(d));
    },
    async session({ session, token }) {
      if (session.user && token.email) session.user.email = token.email;
      return session;
    }
  },
  pages: { signIn: "/", error: "/" }
});
⏱️

Sesión 8h Fija

Sin rolling — el usuario debe re-autenticarse al expirar. Reemplazó la sesión de 30 días por defecto.

Doble Capa de Dominio

1. auth.config.ts callback signIn — bloquea en OAuth.
2. src/middleware.ts — verifica dominio en cada request SSR.

Endpoints del Sistema
GET /api/search src/pages/api/search.ts

Busca archivos en Google Drive. Máximo 6 resultados por query.

Parámetro: ?q=

Query de búsqueda. Mínimo 3 chars, máximo 100. Drive query: name contains '...'. Rate limit: 20 req/min. Cache-Control: private, max-age=10.

// Respuesta 200 — array de hasta 6 resultados
[{ "id": "1hRi0RTpFRDu_Se4AvV3t86qgRD5EuvkK", "name": "Estrategias de Estudio IPG.pdf",
   "mimeType": "application/pdf", "size": "870451" }]
// Errores: 401 sin sesión, 429 rate limit (+ Retry-After), 500 error Drive
GET /api/download src/pages/api/download.ts

Proxy streaming seguro. No expone URLs de Drive. Registra cada descarga en KV.

Parámetro: ?id=

Google Drive file ID. Validación: /^[A-Za-z0-9_-]{25,50}$/. Rate limit: 10 req/min.

Flujo de validaciones

1. getSession() → 2. Regex fileId → 3. Rate limit KV → 4. Token Service Account → 5. Metadata Drive → 6. Stream binario → 7. Log KV (download_log:{timestamp}:{email}).

// Content-Disposition con RFC 6266 (soporta tildes y ñ)
Content-Disposition: attachment; filename="Estrategias.pdf"; filename*=UTF-8''Estrategias%20de%20Estudio.pdf
// Log en KV
{ "email": "alumno@alumnos.ipg.cl", "name": "Alumno IPG", "fileName": "Estrategias.pdf",
  "timestamp": "2026-06-24T12:30:00.000Z", "fileId": "1hRi0..." }
// Errores: 400 fileId inválido, 401 sin sesión, 404 no existe, 429 rate limit, 500 streaming
GET /api/platform-info src/pages/api/platform-info.ts

Credenciales iniciales de plataformas institucionales para alumnos nuevos. Triple validación: sesión + dominio + rate limit. Cache-Control: no-store.

Rate limit: 5 req/min. Fallbacks hardcoded en code: moodle 'ipg.2025', email 'alumnos.2026' (sobreescritos por secrets en producción).

Google Drive Integration

Service Account con scope drive.readonly. Sin SDK oficial — fetch directo a Drive REST API v3.

Flujo de Token (src/lib/googleAuth.ts)

// 1. Verificar caché del Worker isolate (55 minutos)
let _tokenCache: { token: string; expiry: number } | null = null;
if (_tokenCache && now < _tokenCache.expiry) return _tokenCache.token;

// 2. Importar clave privada PKCS8
const privateKey = await importPKCS8(rawKey.replace(/\\n/g, '\n'), 'RS256');

// 3. Firmar JWT RS256 con jose
const jwt = await new SignJWT({
  iss: clientEmail, scope: 'https://www.googleapis.com/auth/drive.readonly',
  aud: 'https://oauth2.googleapis.com/token'
}).sign(privateKey);

// 4. Intercambiar JWT por access token (google OAuth2)
// 5. Cache 55min (token válido 60min, 5min de buffer)
_tokenCache = { token: data.access_token, expiry: now + 55 * 60 * 1000 };
Caché de módulo: search.ts y download.ts comparten el mismo token durante 55 minutos sin doble fetch. La caché se pierde cuando Cloudflare recicla el Worker isolate (típicamente cada 30min).

Cloudflare KV

Namespace

Binding: CRAE_KV

Declarado en wrangler.jsonc bajo kv_namespaces.

Usos

1. Rate Limiting — ventanas fijas por usuario/endpoint con TTL 120s.

Panel de Administración

Ruta /admin (src/pages/admin/index.astro). Verificación via isAdmin(email) en src/lib/admins.ts. Lee env var ADMIN_EMAILS (wrangler secret, lista separada por comas). Fallback hardcoded: luis.rivera@ipg.cl.

Nota: La ruta /api/admin/logs debe existir en src/pages/api/admin/logs.ts. Verificar antes del lanzamiento.

Deploy
# 1. Instalar dependencias
npm install

# 2. Configurar secrets (primera vez)
wrangler secret put AUTH_SECRET
wrangler secret put GOOGLE_CLIENT_ID
wrangler secret put GOOGLE_CLIENT_SECRET
wrangler secret put GOOGLE_DRIVE_PRIVATE_KEY
wrangler secret put GOOGLE_DRIVE_CLIENT_EMAIL
wrangler secret put ADMIN_EMAILS
wrangler secret put MOODLE_PASSWORD
wrangler secret put EMAIL_PASSWORD

# 3. Build — genera dist/ con el Worker compilado
npm run build
# Output: dist/_worker.js/index.js (entry point del Worker)
#         dist/ (assets estáticos: JS, CSS, SVG)

# 4. Deploy a Cloudflare Workers
wrangler deploy
# Lee wrangler.jsonc → sube a craeipg.automatizaciones-730.workers.dev

# Preview local (sin deploy)
npm run dev                # Astro dev server local
wrangler pages dev ./dist  # Simula CF Worker local
Tipo de deploy: Cloudflare Worker con Assets (NO Pages). Diferencia clave: Workers tienen KV access nativo y SSR completo en el edge global.
