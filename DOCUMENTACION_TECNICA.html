Finalidad del Sistema y Casos de Uso

APRENDE+ es el portal educativo institucional del Instituto Profesional IPG. Su propósito es centralizar, organizar y distribuir materiales de apoyo académico para estudiantes y docentes. El acceso es exclusivo para correos @ipg.cl y @alumnos.ipg.cl, autenticados vía Google OAuth 2.0.

👩‍🎓 Casos de Uso — Estudiante

  • 📚 Descargar guías de estudio (Cornell, Pomodoro, APA 7ma)
  • 🔑 Consultar credenciales iniciales de Moodle y Gmail IPG
  • 🎧 Acceder a recursos de bienestar (podcast, trípticos)
  • 🔍 Buscar recursos por nombre o categoría al instante
  • 📅 Consultar calendarios académicos 2026
  • 💻 Acceder a guías del Aula Virtual, Drive y Portal IPG

👨‍💼 Casos de Uso — Administrador

  • 📊 Ver logs de descarga en tiempo real (quién descargó qué)
  • 🔍 Auditar uso de recursos por correo institucional
  • ⚙️ Actualizar credenciales iniciales vía variables de entorno
  • 📁 Agregar recursos nuevos en Google Drive (aparecen automáticamente en búsqueda)
  • 🚀 Deploy a Cloudflare con npm run build
⚠️
Lo que NO hace el sistema: No almacena archivos propios (todo en Google Drive). No tiene base de datos relacional. No gestiona matrículas, notas ni cursos (eso lo hace Moodle). No envía emails. No tiene roles de usuario diferenciados (solo admin vs. no-admin).

Auditoría de Seguridad

✅ Hallazgos Resueltos

1

MissingSecret — auth-astro no arrancaba

RESUELTO

Causa: No existía archivo .env. process.env.AUTH_SECRET era undefined. Aunque el middleware omite la auth en dev, los endpoints /api/auth/* son procesados por auth-astro antes del middleware y fallan sin secret.

✔ Creado .env con AUTH_SECRET generado criptográficamente (32 bytes, base64url)
2

Credenciales hardcodeadas en código fuente

RESUELTO

Archivo: src/pages/api/platform-info.ts
Las contraseñas ipg.2025 (Moodle) y alumnos.2026 (Gmail) estaban como strings literales en el código, visibles para cualquiera con acceso al repositorio.

✔ Movidas a variables de entorno MOODLE_PASSWORD y EMAIL_PASSWORD. Se leen vía runtime env (Cloudflare) o import.meta.env (dev), con fallback a los valores actuales.
3

Credenciales de Google en wrangler.jsonc (versionado en Git)

RESUELTO

Archivo: wrangler.jsonc — sección vars
GOOGLE_CLIENT_ID y GOOGLE_DRIVE_CLIENT_EMAIL estaban en texto plano en un archivo commiteado a Git. Cualquiera con acceso al repo (presente o futuro mediante git log) podía verlos.

✔ Eliminados de vars. Ahora wrangler.jsonc solo contiene AUTH_TRUST_HOST y AUTH_URL (valores no-secretos). Todos los demás deben cargarse con wrangler secret put.
4

Meta generator expone versión de Astro

RESUELTO

Archivo: src/layouts/Layout.astro:19
<meta name="generator" content={Astro.generator} /> publicaba la versión exacta del framework, facilitando ataques dirigidos a CVEs específicas de Astro.

✔ Etiqueta eliminada del layout.
5

.gitignore corrupto — línea malformada

RESUELTO

Archivo: .gitignore
Línea . w r a n g l e r (con espacios entre cada carácter) no ignoraba nada. Posible corrupción por copy-paste. La cobertura de .env* también era incompleta.

✔ Reescrito limpiamente con cobertura completa: .env, .env.local, .env.production, .env.production.local, .wrangler/

⚠️ Hallazgos Pendientes

6

Sin Content Security Policy (CSP)

PENDIENTE

No hay headers CSP en ninguna respuesta. Esto abre la puerta a ataques XSS via inyección de scripts externos. Mínimo necesario: default-src 'self'; script-src 'self' 'unsafe-inline' https://accounts.google.com.

7

Sin rate limiting en APIs

PENDIENTE

/api/search y /api/download no tienen límite de frecuencia. Un usuario autenticado podría generar cientos de requests simultáneos, agotando quota de Google Drive API o generando costos de KV.

8

Email de admin hardcodeado en fuente

BAJO RIESGO

src/lib/admins.ts: ['luis.rivera@ipg.cl']. Aceptable para un único admin, pero cualquier rotación de personal requiere un redeploy de código.

9

Sin monitoreo de errores

PENDIENTE

No hay Sentry, Cloudflare Workers Logpush, ni ningún sistema de alertas. Los errores en producción (console.error) se pierden en los logs de Cloudflare y no generan alertas.

10

Historial Git — credenciales previas

VERIFICAR

Si wrangler.jsonc con GOOGLE_CLIENT_ID fue commiteado y el repositorio es público o fue clonado por terceros, el CLIENT_ID queda en el historial. Evaluar si es necesario rotar las credenciales OAuth.

Análisis de Rendimiento

🐢 Antes (cada request)

  1. Verificar sesión
  2. Leer private key del env
  3. Firmar JWT RS256 (CPU)
  4. Fetch a Google OAuth (~200ms)
  5. Fetch a Drive API
  6. Respuesta al cliente
Latencia extra: ~200-400ms por request

🚀 Después (con cache)

  1. Verificar sesión
  2. getGoogleToken() → cache HIT
  3. Fetch a Drive API
  4. Respuesta al cliente
Latencia del token: <1ms (cache hit en Worker)

Fase 2: Moodle Web Services API

Complejidad: Media

Mostrar en el dashboard de APRENDE+ los cursos activos, próximas entregas y eventos del usuario, consumiendo la API REST de Moodle.

Datos técnicos de la API

# Base URL de la API Moodle IPG
Base: https://aulavirtual.ipg.cl/webservice/rest/server.php
Método: GET (o POST)
Formato: ?moodlewsrestformat=json

# Funciones más útiles para APRENDE+
core_enrol_get_users_courses          → cursos del alumno
core_calendar_get_calendar_upcoming_view → próximas entregas
core_user_get_users_by_field          → perfil del usuario en Moodle
mod_assign_get_assignments            → tareas pendientes
gradereport_user_get_grade_items      → notas del alumno

Flujo propuesto

// Nuevo endpoint: GET /api/moodle/courses
export const GET: APIRoute = async (context) => {
  // 1. Sesión de APRENDE+ (ya autenticado con Google)
  const session = await getSession(context.request)
  const email = session.user.email  // ej: juan.perez@alumnos.ipg.cl

  // 2. Buscar usuario en Moodle por email
  const userRes = await fetch(
    `https://aulavirtual.ipg.cl/webservice/rest/server.php
    ?wstoken=${MOODLE_ADMIN_TOKEN}
    &wsfunction=core_user_get_users_by_field
    &field=email&values[0]=${email}
    &moodlewsrestformat=json`
  )
  const users = await userRes.json()
  const moodleUserId = users[0]?.id

  // 3. Obtener cursos del usuario
  const coursesRes = await fetch(
    `...?wsfunction=core_enrol_get_users_courses
    &userid=${moodleUserId}&moodlewsrestformat=json`
  )
  return new Response(JSON.stringify(courses), { status: 200 })
}
⚠️
Problema clave: El token de admin de Moodle tiene acceso a TODOS los datos de TODOS los usuarios. Debe almacenarse como secret (wrangler secret put MOODLE_ADMIN_TOKEN) y el endpoint debe validar estrictamente que solo retorna datos del usuario autenticado en APRENDE+.
📋
Prerequisitos: El admin de Moodle IPG debe: (1) ir a Administración del Sitio → Plugins → Web Services → Habilitar Web Services, (2) crear un token de servicio externo con las funciones permitidas listadas arriba.
